# NEXA PRIME

منصة اجتماعية متعددة الاستخدامات تجمع الفيديو القصير، الرسائل، القنوات، المجتمعات، الاستوديو، وطبقة أدوات للمطورين في تجربة واحدة متجاوبة.

> **الحالة:** تطبيق ويب تجريبي متكامل مع API وقاعدة بيانات وPWA قابلة للتثبيت على المتصفحات المتوافقة. ليس بعد خدمة إنتاج عامة مدققة؛ النجاح في الاختبارات لا يضمن خلو التطبيق من المشكلات أو الجاهزية القانونية والأمنية.

## التشغيل المحلي

يتطلب Node.js 22 أو أحدث. لتشغيل الحزمة كاملة محليًا عبر Docker، انسخ `.env.example` إلى `.env`، املأ `APP_ORIGIN` وكلمات مرور PostgreSQL والجلسات، ثم شغّل:

```bash
npm ci
npm run infra:up
```

افتح [http://localhost:5173](http://localhost:5173). للتطوير المباشر باستخدام `npm run dev:all`، انسخ العينة إلى `.env.local` وشغّل `docker compose --profile local-storage up -d postgres redis minio`؛ تُربط PostgreSQL وRedis وMinIO بمنافذ loopback فقط لتصل إليها عملية Node على المضيف دون كشفها للشبكة. يطبق الأمر ترحيلات Prisma أولًا، ويمرر Vite `/api` و`/auth` إلى API الداخلي على `127.0.0.1:4001` مع إبقاء المتصفح على origin واحد. إذا كانت قاعدة البيانات قديمة وبها جدول `User`، خذ نسخة احتياطية ثم نفّذ `npm run db:baseline:local` مرة واحدة قبل `npm run dev:all`. يتطلب التسجيل بالبريد إعداد SMTP؛ Google OAuth يعمل بعد ضبط callback. يتطلب تثبيت PWA نطاق HTTPS في بيئة النشر؛ هذه حزمة ويب وليست تطبيق Android أو iOS أصليًا.

للتشغيل المحلي عبر Docker Compose، انسخ العينة إلى `.env` بدلًا من `.env.local`، واملأ `APP_ORIGIN` والأسرار المطلوبة ثم شغّل `npm run infra:up`. يشغّل هذا ملف MinIO التوافقي المحلي ضمن profile `local-storage`، وتبقى منافذ PostgreSQL وRedis محصورة في loopback وشبكة Docker الداخلية. تنفذ الحاوية `prisma migrate deploy` قبل تشغيل API. أنشئ أسرارًا عشوائية منفصلة، مثل `openssl rand -hex 32`.

للإنتاج باستخدام AWS S3 المُدار، اضبط `S3_PROVIDER=aws` و`S3_BUCKET` و`S3_REGION`، واستخدم IAM role أو بيانات اعتماد الخادم؛ لا تشغّل profile `local-storage` ولا تفعّل إنشاء bucket تلقائيًا. يجب إنشاء bucket وسياسة الوصول والتشفير والنسخ الاحتياطي خارج التطبيق.

إذا كان لديك volume PostgreSQL من إصدار سابق يحتوي مخطط `db/schema.sql` كاملًا، خذ نسخة احتياطية أولًا، شغّل الخدمات التابعة، ثم نفّذ baseline مرة واحدة قبل ترقية التطبيق: `docker compose run --rm --no-deps --entrypoint npm app run db:baseline`. لا تستخدمه على قاعدة جديدة أو مخطط غير متحقق منه؛ القواعد الجديدة يجب أن تطبق migration تلقائيًا.

أول حساب يثبت بريده ويحفظ اسم المستخدم `the_x` يصبح المالك. تُحجز الصلاحية على الخادم مرة واحدة، ولا تعتمد على الاسم الظاهر أو بيانات المتصفح.

إعداد Google OAuth للتجربة المحلية:

- **Authorized JavaScript origin:** `http://localhost:5173`
- **Authorized redirect URI:** `http://localhost:5173/auth/google/callback`

للنشر، أضف أصل HTTPS الفعلي وcallback المطابق في إعدادات Google. يشتق التطبيق callback من `APP_ORIGIN` إذا تركت `GOOGLE_REDIRECT_URI` فارغًا، أو استخدم قيمة صريحة مطابقة تمامًا. في Docker الإنتاجي والتطوير تُقدّم الواجهة والـAPI من أصل واحد على المنفذ `5173`. منفذ `4001` داخلي للتطوير فقط، ولا يُنشر للمضيف. لا تشارك `GOOGLE_CLIENT_SECRET` أو مفاتيح API؛ خزّنها في بيئة الخادم فقط.

لتفعيل Google فعليًا، أنشئ OAuth Client من نوع Web في Google Cloud، وسجّل `APP_ORIGIN` كـAuthorized JavaScript origin و`${APP_ORIGIN}/auth/google/callback` كـAuthorized redirect URI، ثم ضع `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` في بيئة الخادم. يجب أن يطابق callback المسجل عنوان التطبيق الخارجي حرفيًا. بعد موافقة Google على البريد الموثق، يُحفظ البريد في حساب NEXA ويطلب التطبيق الاسم المعروض واليوزر قبل فتح الحساب.

بعد تأكيد بريد التسجيل العادي، يعيد الرابط المستخدم إلى صفحة الدخول برسالة نجاح، ثم يُكمل الاسم واليوزر بعد تسجيل الدخول. أخطاء OAuth أو الروابط المنتهية تعرض رسالة داخل التطبيق بدل صفحة JSON خام.

لإرسال إشعارات الرسائل إلى البريد، اضبط `SMTP_HOST` و`SMTP_PORT` و`SMTP_USER` و`SMTP_PASS` في الخادم؛ لإرسال Gmail استخدم App Password لحساب مُفعّل عليه التحقق بخطوتين، وليس كلمة مرور الحساب. يمكن تحديد `SMTP_FROM` إن كان مزود البريد يسمح به. تبقى الإشعارات داخل التطبيق فعالة إذا لم يُضبط SMTP، ولن تُرسل رسائل البريد حتى تضاف بيانات صالحة. يمكن للمستخدم إيقاف بريد التنبيهات من ملفه الشخصي، ولا يحتوي بريد الرسالة على نص المحادثة الخاصة.

في الإنتاج، يخدم التطبيق الواجهة وBackend من أصل واحد على المنفذ `5173`. منافذ PostgreSQL وRedis وMinIO تبقى خاصة بشبكة Docker الداخلية. فحص API متاح عبر `/api/health`.

أوامر التحقق:

```bash
npm run build
npm run preview
npm run db:migrate
```

### العمل دون اتصال

بعد فتح التطبيق مرة واحدة مع اتصال، يخزّن متصفح PWA ملفات الواجهة. تُحفظ الرسائل الصادرة وملفات الفيديو التي تختارها في IndexedDB على الجهاز، وتُزامن عند عودة الاتصال ما دامت الصفحة مفتوحة، أو عند فتح التطبيق مجددًا. تبقى البيانات الواردة التي سبق تحميلها متاحة محليًا على الجهاز نفسه.

هذا وضع offline-first وليس شبكة مراسلة مستقلة: لا تصل الرسائل إلى مستخدم بعيد أثناء انقطاع الإنترنت، ولا تنتقل البيانات بين الأجهزة تلقائيًا دون وسيط متصل. يتطلب التثبيت ودعم التخزين اختلافات حسب المتصفح ونظام التشغيل. الفحص المحلي الحالي قائمة قواعد نصية محدودة، وليس نموذج ذكاء اصطناعي ولا يستطيع فهم السياق أو تحليل الفيديو؛ DeepSeek والخدمات السحابية لا تعمل دون اتصال. لا تمسح بيانات الموقع قبل مزامنة العناصر المنتظرة.

## نطاق NEXA PRIME

### التجربة الاجتماعية

- تغذية فيديو عمودية بأسلوب swipe مع تشغيل تلقائي متجاوب.
- رسائل ومحادثات، قنوات، مساحات، ومجتمعات.
- إنشاء المحتوى عبر NEXA Studio مع واجهات DeepGuard وSafeChat التجريبية.
- ملفات شخصية، متابعة، إعجاب، حفظ، مشاركة، وتبديل الحسابات.
- تخطيط متكيف للهاتف، الجهاز اللوحي، وسطح المكتب.

### الذكاء الاصطناعي

طبقة HyperBrain وDeepSeek اختيارية ومهيأة لتقديم توصيات واقتراحات تطوير وتحليل استخدام. يجب أن تكون التغييرات قابلة للمراجعة، وأن يحتفظ النظام بسجل إصدارات وتاريخ تغييرات append-only. لا تُحذف السجلات القديمة إلا بإجراء مالك موثق يخضع لسياسة الاحتفاظ والخصوصية.

### بوابة المطورين

توجد بوابة `/dev` تجريبية مخفية من التنقل العام، مع مسار أولي للوصول الموثوق، تجارب Draft، تكاملات، ومساعد تطوير. النسخة الحالية تعتمد على حالة المتصفح ولا توفر حماية إنتاجية.

## حالة الإطلاق

الموجود في المستودع: واجهة PWA وAPI، PostgreSQL وRedis عبر Compose، MinIO محلي اختياري أو AWS S3 مُدار، ترحيلات Prisma، تسجيل بالبريد وGoogle، جلسات وتجديد رموز، حماية CSRF، حدود طلبات، إشراف أولي على النص والفيديو، واختبارات تلقائية. تشغيل OAuth والبريد وفحص AWS يحتاج بيانات اعتماد وخدمات يملكها مشغّل التطبيق. صورة MinIO المحلية من أرشيف Bitnami مخصصة للتطوير والتوافق فقط وليست خدمة مدعومة للإنتاج.

قبل فتح التسجيل للجمهور: انشر على نطاق HTTPS تملكه، اضبط الأسرار والبريد وGoogle OAuth، طبّق النسخ الاحتياطي واختبر الاستعادة، أضف MFA ومراقبة وتنبيهات واختبارات تحميل واختراق، وأكمل مراجعة الخصوصية والإشراف والدعم وخطة الاستجابة للحوادث. إعداد Compose الحالي مناسب للنشر الأحادي التجريبي، وليس بنية عالية التوفر أو متعددة النسخ.

التطبيق القابل للتنزيل حاليًا هو PWA من المتصفح. نشر تطبيق أصلي على متجري Google Play وApple App Store يتطلب مشروع تغليف/تطوير منفصلًا، حسابات مطورين، توقيعًا، واختبارات أجهزة ومراجعة المتاجر.

## نموذج الأمان

نمط النقر وبصمة الجهاز مناسبان كطبقة UX إضافية، لكنهما لا يمكن أن يكونا وسيلة المصادقة الوحيدة: كود الواجهة و`localStorage` قابلان للفحص والتعديل من صاحب الجهاز. يجب أن تتم صلاحيات المطور الحساسة على الخادم باستخدام MFA، مفاتيح WebAuthn أو مفاتيح أجهزة، وموافقة متعددة عند العمليات عالية الخطورة.

كما أن MutationObserver وShadow DOM لا يمنعان تعديل DOM من أدوات المطور. الحماية الحقيقية تكون عبر حدود الخادم، التوقيع، التفويض، التدقيق، والمراقبة. لا تعتمد على فحص المتصفح كل 0.5 ثانية كضمان أمني.

## تحقيق الدخل

مسارات غير مفروضة على المستخدم: إعلانات خفيفة داخل Explore، محتوى وقنوات مدعومة، وميزات سوق مجانية ومدفوعة للشركات والمبدعين. يجب أن تكون الإعلانات معلنة، قابلة للضبط، متوافقة مع الخصوصية، وألا تستخدم بيانات حساسة دون موافقة.

## الأسرار ومفاتيح API

لا تضع مفاتيح DeepSeek أو Google أو أي بيانات اعتماد في README أو JavaScript أو Git. استخدم ملفًا محليًا غير متتبع مثل `.env.local`، ومرّر المفاتيح إلى Backend فقط. المفتاح الذي ظهر في أي مواصفة أو محادثة يجب اعتباره مكشوفًا وإلغاؤه وإصدار بديل له.

يخزن Backend المستخدمين والمحتوى في PostgreSQL، والجلسات وحالة OAuth وحدود المعدل في Redis. مخطط قاعدة البيانات يُدار عبر `prisma/migrations`؛ خذ نسخة احتياطية واختبر أي migration على نسخة staging قبل تطبيقها على بيانات الإنتاج. لا توجد نسخ احتياطية مُدارة أو توافر عالٍ ضمن Compose. كما أن اتصالات WebSocket وعدادات التشغيل محلية للعملية، لذا يتطلب التوسع إلى عدة نسخ آلية بث مشتركة ومراقبة إنتاجية.

### الإشراف على المحتوى

يضبط المشغّل `DEEPSEEK_API_KEY` في الخادم فقط لتفعيل فحص DeepSeek للنصوص الجديدة قبل حفظ المنشورات والتعليقات والرسائل والملفات الشخصية والقنوات. يصنّف النصوص المتعلقة بالقذف/الادعاءات الضارة، والتحريض الطائفي أو القبلي أو السياسي على الكراهية أو العنف، والتحرش، والمحتوى الجنسي الصريح؛ المحتوى الملتبس يُرفض ويطلب إعادة صياغته. تُفحص قائمة الكلمات والروابط محليًا أولًا لتجنب استدعاءات غير لازمة، ثم تُخزّن نتيجة النص المتطابق في Redis لمدة 24 ساعة، مع حد مخرجات صغير لتقليل التكلفة. عند غياب المفتاح أو تعذر DeepSeek في الإنتاج، يفشل حفظ المحتوى المغطى بالفحص بأمان بدل تمريره دون فحص. لا يضمن أي مصنف آلي اكتشاف كل الحالات أو صحة الأحكام؛ راجع البلاغات والقرارات الخاطئة بشريًا.

يرسل الخادم نص المحتوى إلى DeepSeek عند الحاجة للفحص؛ لا ترسل مفاتيح API أو نصوص المستخدم إلى الواجهة أو سجلات التطبيق. حدّث سياسة الخصوصية وأفصح للمستخدمين عن مزود المعالجة والاحتفاظ قبل الإطلاق. `CONTENT_BLOCKLIST` يضيف كلمات محلية مفصولة بفواصل، لكنه ليس بديلًا عن الفهم السياقي.

تُرفض عناوين النطاقات في النصوص افتراضيًا، ويمكن للمالك المسجل إضافتها أو إزالتها من «سياسة الروابط» في مركز المطورين؛ تشمل الإضافة النطاقات الفرعية، وتُحفظ القائمة وسجل تغييراتها ومحاولات الرفض في Redis/سجل الإشراف. المطابقة تطبّع بعض الصيغ الشائعة مثل `hxxp` و`[.]` و`dot`، لكنها ليست كاشفًا شاملًا للتحايل اللغوي، ولا تفحص نصوصًا مستخرجة من الفيديو أو الصور. لا تعتبر هذه السياسة ضمانًا أمنيًا مستقلًا.

DeepSeek النصي لا يحلل ملفات الفيديو. لفحص الفيديو آليًا، يلزم إعداد `AWS_REGION` و`AWS_S3_BUCKET` و`AWS_REKOGNITION_SNS_TOPIC_ARN` و`AWS_REKOGNITION_ROLE_ARN` وصلاحيات IAM مناسبة؛ الفحص التلقائي الحالي مخصص لـMP4 وMOV/QuickTime. يُرفع الفيديو مؤقتًا إلى S3 لفحص Rekognition ثم يحذفه التطبيق بعد اكتمال المهمة. الفيديوهات التي تصنفها الخدمة أو يفشل فحصها تبقى مخفية للمراجعة البشرية. دون الإعدادات أو للصيغ الأخرى، لا يُعتمد الفيديو تلقائيًا ويبقى في طابور المراجعة؛ لا تعتبره مفحوصًا آليًا. أضف قاعدة S3 lifecycle لحذف الملفات المؤقتة المتروكة، وأفصح عن معالجة AWS قبل التفعيل.

## مبادئ التطوير

- لا نحذف تفاصيل أو إعدادات أو سجلات قديمة بصمت.
- كل تغيير مهم يملك سجلًا وإصدارًا وإمكانية مراجعة.
- الواجهة تتكيف مع الجهاز دون التضحية بإمكانية الوصول.
- الميزات التجريبية تحمل حالة واضحة ولا تُعرض كضمانات إنتاجية.
- أي قرار أمني يُنفذ على الخادم، لا في الواجهة وحدها.
